The **Credit Usage** page provides a detailed record of how credits are allocated, consumed, and returned across your Valuez AI workspace.

Use this page to:

- Check your available credit balance
- Review total account credits
- See how many credits have been used
- Filter usage by service
- Analyze usage over a selected date range
- Review usage quantities and rates
- Identify individual sessions
- Track credits that were returned
- Download usage data as a CSV file
- Purchase additional credits

<Info>
  Credit Usage is a reporting page. It explains how workspace credits changed, but it does not replace payment and receipt information available on the Billing page.
</Info>

---

## Open Credit Usage

You can open Credit Usage from the Billing page or the dashboard navigation.

<Steps>
  <Step title="Open Billing">
    Open **Billing** in your Valuez AI workspace.
  </Step>
  <Step title="Find the credit balance">
    Locate the card showing your available credits.
  </Step>
  <Step title="Select View usage logs">
    Click **View usage logs**.
  </Step>
  <Step title="Review credit activity">
    Valuez AI opens the Credit Usage page with the last 30 days selected by default.
  </Step>
</Steps>

## Credit Summary

The top of the page displays three credit summary cards.

<Tabs>
  <Tab title="Available Credits">
    **Available credits** shows the credit balance currently available for supported Valuez AI operations.

    This is the balance you should review before:

    - Starting an outbound campaign
    - Increasing concurrent calling
    - Running high-volume speech processing
    - Using Voice Agent APIs
    - Performing large numbers of AI requests
  </Tab>
  <Tab title="Credits Used">
    **Account credits used** shows the credits already consumed from the account allocation.

    This value is based on the current credit summary for the active workspace.
  </Tab>
  <Tab title="Total Credits">
    **Total account credits** shows the complete credit allocation associated with the current account or subscription period.
  </Tab>
</Tabs>

| Summary | Meaning |
| --- | --- |
| **Available credits** | Credits that remain available |
| **Account credits used** | Credits already consumed |
| **Total account credits** | Complete allocated credit quantity |

<Warning>
  The figures belong to the active workspace. If your account can access multiple workspaces, confirm that you selected the correct workspace before reviewing usage.
</Warning>

## Default Reporting Period

When you open Credit Usage, the default reporting period is the most recent 30 days, including the current day.

The page uses this period for:

- Total credits used
- Service breakdown
- Usage trend
- Detailed usage history
- CSV export

You can change the reporting period with the date-range selector.

## Select a Date Range

Use the date-range selector to analyze credit usage for a specific period.

<Steps>
  <Step title="Open the date selector">
    Click the date-range control above the usage report.
  </Step>
  <Step title="Choose the starting date">
    Select the first date to include.
  </Step>
  <Step title="Choose the ending date">
    Select the last date to include.
  </Step>
  <Step title="Apply the range">
    Apply the selection to refresh the report.
  </Step>
</Steps>

The selected date range affects:

- Total credits used
- Number of ledger entries
- Credits returned
- Usage breakdown
- Usage trend
- Detailed usage history
- CSV exports

### Maximum date range

The page supports a maximum selected period of **366 days**.

If you select a longer period, Valuez AI displays:

```text
Select a date range of 366 days or fewer.
```

### Reset the date range

Use the reset control in the date selector to return to the default last-30-days period.

## Refresh Credit Usage

Use the refresh button beside the date selector to retrieve the latest usage information.

The refresh icon rotates while Valuez AI loads the report.

Refresh the page after:

- Completing a large call campaign
- Purchasing additional credits
- Receiving returned credits
- Testing an API integration
- Making multiple inbound or outbound calls
- Changing the selected workspace

<Note>
  Very recent activity may require a short processing period before appearing in the ledger.
</Note>

## Total Credits Used

The report summary displays the total number of credits consumed by the selected service category during the selected period.

It also displays:

- Active service filter
- Selected date range
- Number of ledger entries
- Credits returned, when applicable

For example:

```text
245.75 credits
Phone calls
01 Oct 2026 – 10 Oct 2026
32 ledger entries
```

If credits were returned during the same period, the summary can also display the returned quantity.

## Understanding Ledger Entries

A ledger entry is an individual credit event recorded by Valuez AI.

An entry can represent:

- A call charge
- Speech recognition
- Voice generation
- AI-response processing
- An API request
- An internal agent test
- Website-agent activity
- A virtual-number purchase
- A virtual-number renewal
- A credit return or correction

One conversation can create multiple entries if it uses multiple billable services.

<Info>
  The number of ledger entries is not necessarily the same as the number of calls or conversations.
</Info>

## Credit Changes

The Credit Change column uses signs and colors to distinguish deductions from returns.

<Tabs>
  <Tab title="Credits Deducted">
    A deduction is displayed with a minus sign in red.

    Example:

    ```text
    −2.75
    ```
  </Tab>
  <Tab title="Credits Returned">
    A returned credit amount is displayed with a plus sign in green.

    Example:

    ```text
    +1.50
    ```
  </Tab>
  <Tab title="No Change">
    A zero-value entry is displayed as:

    ```text
    0
    ```
  </Tab>
</Tabs>

Credits can be returned because of a correction, failed operation, reversal, or another billing adjustment recorded by the platform.

## Session IDs

When available, each usage entry includes a **Session ID**.

A Session ID can help you correlate credit usage with:

- A call
- An agent test
- An API request
- A website conversation
- A voice session
- A support investigation

Session IDs appear in a monospaced format and may be shortened visually when they are long.

On desktop, move your pointer over the value to review the full identifier when supported by the browser.

<Tip>
  Copy the relevant Session ID before contacting support about a specific usage charge.

## Download Usage as CSV

Click **Download CSV** in the page header to export usage records.

The export includes every matching entry for the selected:

- Workspace
- Service category
- Starting date
- Ending date

It is not limited to the entries currently visible on the page.

<Steps>
  <Step title="Select a service">
    Choose **All usage** or a specific service category.
  </Step>
  <Step title="Select the date range">
    Choose the period to include in the export.
  </Step>
  <Step title="Select Download CSV">
    Click **Download CSV** in the page header.
  </Step>
  <Step title="Wait for preparation">
    The button displays **Preparing CSV…** while Valuez AI retrieves all matching records.
  </Step>
  <Step title="Save the file">
    Your browser downloads the generated CSV file.
  </Step>
</Steps>

### CSV filename

The filename follows this format:

```text
valuez-credit-usage-[category]-[from-date]-to-[to-date].csv
```

Example:

```text
valuez-credit-usage-calls-2026-10-01-to-2026-10-10.csv
```

### CSV columns

The export contains:

| Column | Description |
| --- | --- |
| **Activity** | User-friendly activity name |
| **Source** | Origin of the activity |
| **Usage details** | Duration, characters, tokens, or another quantity |
| **Rate** | Recorded service rate |
| **Date** | Usage timestamp |
| **Session** | Associated Session ID |
| **Credits used** | Credits deducted |
| **Credits returned** | Credits added back |

<Note>
  The Download CSV button is disabled when the report is loading, an export is already running, or no matching records exist.
</Note>

---

## Export Consistency

Valuez AI retrieves export records in batches and keeps the export aligned with the selected report.

If usage changes while the export is being prepared and the records can no longer be retrieved consistently, the page can display:

```text
Usage changed during export. Please refresh and try again.
```

If this occurs:

1. Refresh the usage report.
2. Confirm the selected service and dates.
3. Start the export again.

## Reconcile a Usage Charge

Use the following process when investigating a credit charge:

<Steps>
  <Step title="Select the relevant date range">
    Limit the report to the approximate time of the activity.
  </Step>
  <Step title="Select the service category">
    Choose calls, Speech to Text, Text to Speech, AI responses, voice agents, or phone numbers.
  </Step>
  <Step title="Find the ledger entry">
    Review the activity, source, quantity, rate, date, and credit change.
  </Step>
  <Step title="Copy the Session ID">
    Record the Session ID when one is available.
  </Step>
  <Step title="Compare related records">
    Check Call Logs, Speech API History, campaign records, or integration activity.
  </Step>
  <Step title="Export the report">
    Download the CSV when you need to share multiple entries with an administrator or support team.
  </Step>
</Steps>

## Best Practices

<AccordionGroup>
  <Accordion title="Review usage regularly">
    Review the Credit Usage page regularly instead of waiting until the available balance is nearly exhausted.
  </Accordion>

  <Accordion title="Check usage before large campaigns">
    Review available credits and recent consumption before starting a high-volume outbound campaign.
  </Accordion>

  <Accordion title="Use service filters">
    Filter the report before investigating a charge. This makes it easier to isolate calls, speech operations, AI responses, or phone-number costs.
  </Accordion>

  <Accordion title="Use shorter date ranges for investigations">
    A shorter date range produces a more focused chart, breakdown, history, and CSV export.
  </Accordion>

  <Accordion title="Preserve Session IDs">
    Include Session IDs when reporting unexpected charges. They provide a direct reference for investigating individual usage events.
  </Accordion>

  <Accordion title="Export data for reconciliation">
    Download periodic CSV reports for accounting, operational review, and internal cost analysis.
  </Accordion>

  <Accordion title="Monitor returned credits">
    Returned credits appear as positive green values. Include them when calculating net consumption.
  </Accordion>

  <Accordion title="Do not compare ledger entries only by count">
    Different entries can consume different quantities of credits. Compare the recorded quantity, rate, and credit change.
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Credit usage does not load">
    Click the refresh button and try again.

    If the problem continues:

    1. Confirm that your internet connection is working.
    2. Check that the correct workspace is active.
    3. Reset the date range to the last 30 days.
    4. Select All usage.
    5. Sign out and sign in again.
  </Accordion>

  <Accordion title="Credit usage is temporarily unavailable">
    This message can appear when the reporting service does not return the required analytics information.

    Refresh the page after a short wait. If the problem continues, contact Valuez AI support.
  </Accordion>

  <Accordion title="No usage appears for the selected period">
    Confirm that:

    - The selected dates include the activity
    - The correct service category is selected
    - The correct workspace is active
    - The activity consumed credits
    - The usage record has finished processing

    Select **All usage** and expand the date range if necessary.
  </Accordion>

  <Accordion title="The summary and visible table do not match">
    The summary represents all matching records for the selected service and date range.

    The history table displays only the current page. Use pagination or download the CSV to review all entries.
  </Accordion>

  <Accordion title="I cannot select a date range longer than one year">
    Credit Usage limits a selected range to 366 days.

    Export multiple smaller date ranges if you need more than one year of data.
  </Accordion>

  <Accordion title="The usage trend is empty">
    Confirm that matching credit activity exists for the selected period and service.

    Try:

    1. Selecting All usage.
    2. Resetting to the last 30 days.
    3. Changing the interval to Auto.
    4. Refreshing the report.
  </Accordion>

  <Accordion title="The Session ID is missing">
    Not every usage event has an associated Session ID.

    Use the activity type, source, date, usage detail, and credit change to identify the event.
  </Accordion>

  <Accordion title="Download CSV is disabled">
    The button is disabled when:

    - The report is loading
    - Another export is being prepared
    - No matching records exist

    Wait for loading to finish or change the filters to a period containing usage.
  </Accordion>

  <Accordion title="CSV export failed">
    Click **Try again**.

    If it continues:

    1. Refresh the report.
    2. Use a shorter date range.
    3. Confirm that usage records exist.
    4. Start a new export.
  </Accordion>

  <Accordion title="Usage changed during export">
    New credit activity changed the ledger while the export was being prepared.

    Refresh the page and download the CSV again.
  </Accordion>

  <Accordion title="The CSV does not contain only the visible rows">
    This is expected. The CSV contains all matching entries for the selected workspace, service, and dates, not only the current table page.
  </Accordion>

  <Accordion title="Credits were deducted unexpectedly">
    Review the activity, source, quantity, rate, timestamp, and Session ID.

    Then compare the entry with:

    - Call Logs
    - Campaign activity
    - Speech API History
    - Agent testing
    - API integrations
    - Virtual phone-number activity

    Contact support if you still cannot identify the charge.
  </Accordion>

  <Accordion title="A returned credit is displayed with a plus sign">
    This is expected. A positive green value indicates that credits were added back to the balance.
  </Accordion>

  <Accordion title="Recently purchased credits are not visible">
    Refresh the page and check Billing Payment History.

    Do not repeat the purchase until you confirm the status of the original payment.
  </Accordion>

  <Accordion title="Add Credits does not open">
    Refresh the page and try again.

    Confirm that your browser is not blocking required scripts, dialogs, or payment redirects.
  </Accordion>
</AccordionGroup>
