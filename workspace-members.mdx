Workspace Members lets workspace owners and authorized administrators control who can access their Valuez AI organization and what each person can do.

You can invite one or more members, select their platform access, decide which AI agents they can use, configure module permissions, monitor invitation status, update existing access, reset registered mobile-device information, and remove members from the workspace.

<Frame caption="Workspace Members">
  ![Workspace Members page showing member access, platform, permissions, status, and administrative actions](/images/workspace-members.png)
</Frame>

<Info>
  Workspace membership is different from Sales Team performance. Workspace Members controls application access and permissions. Sales Team tracks salespeople, assigned customers, calls, and performance.
</Info>

---

## Open Workspace Members

<Steps>
  <Step title="Sign in to Valuez AI">
    Sign in using a workspace-owner or authorized administrator account.
  </Step>
  <Step title="Open Settings & Billing">
    Select **Settings & Billing** from the main navigation.
  </Step>
  <Step title="Select Workspace Members">
    Click **Workspace Members** under Workspace & Account.
  </Step>
</Steps>

The dashboard route is:

```text
/user-management-new
```

---

## What You Can Do

Depending on your plan and permissions, Workspace Members lets you:

- Review workspace owners, members, and invitations
- Search by member name or email address
- Filter members by platform access
- Review active, pending, expired, and plan-disabled access
- Invite one or multiple people
- Invite members to the web application
- Invite members to the mobile application
- Provide combined web and mobile access
- Grant access to all AI agents
- Limit access to selected AI agents
- Configure module-level permissions
- Configure available actions inside each module
- Edit an active member's access
- Remove an active member from the workspace
- Review plan seat limits
- Reset a registered mobile-device IMEI
- Review pending invitation expiration

## Workspace Members and Invite Members

The page has two primary views:

| View | Purpose |
| --- | --- |
| **Workspace Members** | Review and manage owners, active members, and invitations |
| **Invite Members** | Add new people and configure their access |

When editing an existing user, **Invite Members** changes to **Edit Member**.

The count displayed beside Workspace Members represents the available active-member count returned by the workspace.

## Plan and Seat Availability

The plan banner shows which membership capabilities are available.

It can display:

- Current plan name
- Permission level
- Occupied Web App seats
- Total Web App seat limit
- Occupied Mobile App seats
- Total Mobile App seat limit
- Whether the subscription is active
- Whether a platform limit has been reached
- Whether invitations are disabled

Example:

```text
Web App: 3 / 5 seats
Mobile App: 2 / 3 seats
```

<Info>
  Pending invitations reserve seats. The workspace owner is excluded from the member-seat count.
</Info>

### Combined access and seats

A member with **Web & Mobile** access consumes:

- One Web App seat
- One Mobile App seat

Before sending an invitation, ensure that both platform types have an available seat.

### Plan restrictions

The page can display notices such as:

```text
The subscription is inactive or expired. Renew to restore member access.
```

```text
Member invitations are disabled on this plan. Upgrade to enable access.
```

```text
A platform limit is reached. Free a seat on that platform or upgrade.
```

<Warning>
  Invitations can be unavailable even when your account is active if the selected platform has reached its seat limit.
</Warning>

## Member Table

Each row represents one of the following:

- Workspace owner
- Active workspace member
- Pending invitation
- Expired invitation
- Member disabled by the current plan

The desktop table contains:

| Column | What It Shows |
| --- | --- |
| **Member** | Member name, email, role, or invitation-expiration information |
| **Platform Access** | Web App, Mobile App, or Web & Mobile |
| **Agent Access** | Whether the member can access all agents or selected agents |
| **Permissions** | Summary of the member's module access |
| **Device ID (IMEI)** | Registered mobile-device identifier, when available |
| **Status** | Active, Pending Invite, Expired, or Disabled by plan |
| **Actions** | Edit or remove controls when available |

On mobile devices, this information is displayed in member cards.

## Platform Access

Valuez AI supports three member-access configurations.

### Mobile App

Mobile App access provides permissions for mobile sales and calling modules.

Use it for people who primarily:

- Use the Valuez mobile application
- Make or manage sales calls from mobile
- Work with assigned contacts
- Do not require the complete web dashboard

### Web App

Web App access provides permissions for web-platform modules and dashboards.

Use it for people who:

- Manage AI agents
- Review conversations and analytics
- Work with campaigns
- Configure integrations
- Use administration features
- Work primarily from the web dashboard

### Web & Mobile

Web & Mobile provides access to both sets of modules, subject to the selected permissions.

Use it when a person needs:

- Web-dashboard administration
- Mobile sales or calling capabilities
- Access to workflows across both platforms

<Warning>
  Grant only the platform access required for the person's responsibilities. Combined access consumes both a Web App seat and a Mobile App seat.
</Warning>

## Agent Access

Agent Access controls which AI agents a member can use.

Available options depend on the workspace plan.

### All Agents

All Agents gives the member access to:

- Every current agent in the workspace
- Agents created in the future

The interface displays:

```text
Invited members will have access to all current and future agents in this workspace.
```

Use this option for trusted administrators who need broad agent access.

### Specific Agents

Specific Agents limits the member to selected AI agents.

When selected, use the agent picker to choose one or more agents.

This option is useful when:

- Teams manage different departments
- Sales and support agents must remain separate
- Customer information should be restricted
- External contractors require limited access
- Regional teams use different agents

<Note>
  Specific-agent selection depends on the permission level included with your subscription plan.
</Note>

### Specific-agent requirement

If Specific Agents is selected, at least one agent must be chosen before the invitation or access update can be saved.

## Permission Levels and Plans

Permission controls depend on the current workspace plan.

The interface can support progressively more detailed access models:

| Permission Level | General Capability |
| --- | --- |
| **No team access** | Member invitations are unavailable |
| **Basic access** | Select which modules the member can use |
| **Agent and module-level access** | Select modules and supported access levels |
| **Custom and granular access** | Configure individual actions and custom permission sets |

<Info>
  The exact controls displayed in your workspace are determined by the active subscription plan.
</Info>

---

## Common Permission Actions

Depending on the module and plan, permissions can include actions such as:

- View
- Create
- Update
- Delete
- Download
- Payment

Not every action is available for every module.

### View

Allows the member to open and review module information.

### Create

Allows the member to create new records where supported.

### Update

Allows the member to change existing records or configuration.

### Delete

Allows the member to remove records where supported.

### Download

Allows the member to download data, recordings, or exports where supported.

### Payment

Allows access to payment-related actions.

<Warning>
  Payment permission is highly sensitive. Grant it only to explicitly authorized financial or administrative users.
</Warning>

---

## Permission Dependencies

Some permissions depend on other permissions.

For example:

- A person generally needs View access before managing a module.
- Configuration access can depend on access to the parent agent.
- Knowledge-base document access can depend on knowledge-base access.
- Some actions may automatically enable required parent permissions.
- Removing a parent permission can remove dependent access.

Review the complete permission summary before saving.

## Invite Workspace Members

Open **Invite Members** to add people to the workspace.

<Frame caption="Invite Workspace Members">
  ![Invite Workspace Members form showing email, platform, agent, and module-access controls](/images/invite-workspace-members.png)
</Frame>

The invitation process has four main parts:

1. Add email addresses
2. Select platform access
3. Select agent access
4. Configure module permissions

---

## Add Email Addresses

Enter one or more email addresses in the invitation field.

Example:

```text
first@example.com, second@example.com
```

Multiple email addresses can be separated using:

- Commas
- Semicolons
- Spaces
- Line breaks or other whitespace

The page displays how many recipients are ready.

Example:

```text
2 recipients ready to invite
```

Invalid addresses are identified before submission.

<Info>
  Duplicate email addresses entered in the same invitation are automatically reduced to one address.
</Info>

---

## Send Multiple Invitations

The same access configuration is applied to every valid email address submitted together.

Before inviting multiple people, confirm that they should all receive:

- The same platform access
- The same agent scope
- The same selected agents
- The same module permissions
- The same action-level access

If different people need different permissions, invite them separately.

## Complete the Invitation

<Steps>
  <Step title="Open Invite Members">
    Select the Invite Members tab.
  </Step>
  <Step title="Enter email addresses">
    Add one or more valid email addresses.
  </Step>
  <Step title="Select platform access">
    Choose Mobile App, Web App, or Web & Mobile.
  </Step>
  <Step title="Select agent access">
    Choose All Agents or Specific Agents.
  </Step>
  <Step title="Select agents when required">
    If using Specific Agents, choose at least one agent.
  </Step>
  <Step title="Configure module permissions">
    Enable only the modules and actions required by the invited users.
  </Step>
  <Step title="Review seat availability">
    Confirm that the selected platform has enough available seats.
  </Step>
  <Step title="Send invitations">
    Click **Send Invitations**.
  </Step>
</Steps>

The action button can display guidance such as:

```text
Add an email address
```

```text
Fix invalid email address
```

```text
Select at least one module
```

```text
Select at least one agent
```

```text
Adding member...
```

## Invitation Results

After submission, Valuez AI reports the outcome.

The result can include:

- Invitations sent
- Addresses already belonging to members
- Failed invitations

Example:

```text
2 invitations sent, 1 already a member.
```

If an email address already belongs to a workspace member, a duplicate membership is not created.

---

## Pending Invitations

An invitation remains pending until the recipient accepts it.

Pending invitations:

- Appear in the member list
- Display Pending Invite status
- Can show an expiration date
- Reserve platform seats
- Do not provide active workspace access until accepted

If an invitation expires, invite the person again if access is still required.

<Note>
  The current frontend does not expose a revoke-invitation action in the visible interface.
</Note>

---

## Invitation Acceptance

The recipient must:

1. Open the invitation email.
2. Follow the invitation link.
3. Sign in or create the required account.
4. Accept access to the workspace.
5. Use the correct web or mobile platform.

If the recipient cannot find the email, ask them to check:

- Spam or junk folder
- Email security quarantine
- Correct spelling of the address
- Corporate email filtering
- Whether the invitation expired

## Edit Member Access

Active non-owner members can display an Edit action.

<Frame caption="Edit workspace member access">
  ![Edit Workspace Member screen showing platform, agent, and module permissions](/images/edit-workspace-member.png)
</Frame>

You can update:

- Platform access
- Agent access scope
- Selected agents
- Module permissions
- Available action permissions

### Edit a member

<Steps>
  <Step title="Find the member">
    Search or filter the Workspace Members list.
  </Step>
  <Step title="Click Edit">
    Select the edit icon under Actions.
  </Step>
  <Step title="Review current access">
    Wait for the saved access configuration to load.
  </Step>
  <Step title="Update platform access">
    Select the platform required by the member.
  </Step>
  <Step title="Update agent access">
    Choose All Agents or Specific Agents.
  </Step>
  <Step title="Update module permissions">
    Enable or remove module and action access.
  </Step>
  <Step title="Save the changes">

  </Step>
</Steps>

A successful update displays:

```text
Member Name's access was updated.
```

## Changing Platform Access

Changing a member's platform can change the modules available for configuration.

For example:

- Changing from Web App to Mobile App replaces web modules with mobile modules.
- Changing to Web & Mobile can consume a seat from both limits.
- Changing platform access can reset or alter incompatible permissions.

Review all module permissions after changing the platform.

## Remove a Member

The Remove action is available for eligible active members.

Removing a member:

- Removes the person's access to the workspace
- Does not delete the person's own Valuez AI account
- Can free the associated workspace seat
- Requires confirmation

The confirmation explains:

```text
Their own account will not be deleted.
```

<Warning>
  Removing a member affects access immediately after the operation succeeds. Confirm that ownership of important workflows and responsibilities has been transferred first.
</Warning>

### Before removing a member

Check:

- Whether the person owns operational responsibilities
- Whether they manage active agents or campaigns
- Whether API keys or integrations require rotation
- Whether assigned sales customers need reassignment
- Whether downloaded customer information should be recovered or deleted
- Whether the change follows your offboarding policy

---

## Workspace Owner

The workspace owner appears in the member list but does not display normal edit or remove actions.

The owner:

- Is excluded from seat counts
- Has broad workspace control
- Cannot be managed like a regular member through the visible member actions

Ownership changes should be handled through the supported account-administration process.

## Device ID (IMEI)

Mobile App members can have a registered Device ID or IMEI.

The Device ID helps associate mobile access with a registered device.

When an IMEI is present, select it to open the reset confirmation.

The confirmation displays:

```text
Reset Registered Device?
```

and:

```text
Are you sure to reset this IMEI number?
```

### Reset an IMEI

Reset the device identifier when:

- The member receives a new phone
- The original phone is lost or replaced
- Mobile login remains associated with an old device
- An administrator approves a device-registration reset

<Warning>
  Resetting an IMEI changes the member's registered-device state. Verify the member's identity before performing the reset.
</Warning>

## Recommended Access Model

Apply the principle of least privilege:

```text
Give each member only the access required for their responsibilities.
```

### Example: Support reviewer

A support reviewer may require:

- Web App
- Specific support agents
- View conversations
- View call logs
- No billing access
- No delete access

### Example: Agent administrator

An agent administrator may require:

- Web App
- Selected or all agents
- View and update agent configuration
- Knowledge-base access
- Test access
- No payment access

### Example: Mobile salesperson

A salesperson may require:

- Mobile App
- Mobile sales and calling modules
- Assigned customer access
- No web administration access

### Example: Operations administrator

An operations administrator may require:

- Web & Mobile
- All agents
- Operational modules
- Team and integration access
- Billing only when explicitly authorized

Workspace owners should review access regularly.

<Check>
  Every active member still requires workspace access.

<Check>
  Pending invitations are expected and have not remained unused unnecessarily.
</Check>

<Check>
  Platform access matches each person's actual responsibilities.
</Check>

<Check>
  Specific-agent access is used when broad access is unnecessary.
</Check>

<Check>
  Module permissions follow least-privilege principles.

<Check>
  Delete, download, and payment permissions are tightly restricted.
</Check>

<Check>
  Former employees and contractors have been removed.
</Check>

<Check>
  Mobile-device registrations remain valid.
</Check>

<Check>
  Seat usage remains within plan limits.

## Best Practices

<AccordionGroup>
  <Accordion title="Invite users individually when access differs">
    Send separate invitations when users require different platform, agent, or module permissions.
  </Accordion>

  <Accordion title="Use specific-agent access">
    Limit users to selected agents when they do not need workspace-wide visibility.
  </Accordion>

  <Accordion title="Restrict sensitive actions">
    Grant delete, download, billing, and payment actions only to explicitly authorized users.
  </Accordion>

  <Accordion title="Review pending invitations">
    Pending invitations reserve seats. Reassess invitations that remain unused.
  </Accordion>

  <Accordion title="Remove access promptly">

  </Accordion>

  <Accordion title="Review access after role changes">

  </Accordion>

  <Accordion title="Verify device resets">
    Confirm the member's identity before resetting a registered mobile device.
  </Accordion>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Invite Members is unavailable">
    Check whether the subscription is active, member invitations are included, and the selected platform has an available seat.
  </Accordion>

  <Accordion title="The selected platform is disabled">
    The current workspace plan may not include that platform. Review Subscription & Plans.
  </Accordion>

  <Accordion title="An email address is rejected">
    Confirm that the address uses a valid format and does not contain extra punctuation.
  </Accordion>

  <Accordion title="Send Invitations remains disabled">
    Add at least one valid email address, select an available platform, grant at least one usable module, and select an agent when using Specific Agents.
  </Accordion>

  <Accordion title="The person is already a member">
    Search the Workspace Members list using the person's email address. Update their existing access instead of sending another invitation.
  </Accordion>

  <Accordion title="The recipient did not receive the invitation">
    Check the address, spam folder, security quarantine, and invitation expiration. Corporate email filtering may delay delivery.
  </Accordion>

  <Accordion title="A pending invitation uses a seat">
    This is expected. Pending invitations reserve the relevant Web or Mobile seat.
  </Accordion>

  <Accordion title="Specific Agents is unavailable">
    The current plan's permission level may support only All Agents. Review Subscription & Plans.
  </Accordion>

  <Accordion title="A module is not displayed">
    Confirm that the module belongs to the selected platform and is included in the current plan.
  </Accordion>

  <Accordion title="Permissions cannot be saved">
    Confirm that the platform is enabled and at least one usable permission remains selected.
  </Accordion>

  <Accordion title="A member is disabled by plan">
    The subscription may be inactive, expired, or over its seat allowance. Review the plan banner and Subscription & Plans.
  </Accordion>

  <Accordion title="The Remove action is unavailable">
    Owners, pending invitations, expired invitations, or restricted records may not provide normal member actions.
  </Accordion>

  <Accordion title="The member cannot access an agent">
    Review Agent Access and confirm that the agent is selected or that All Agents is enabled.
  </Accordion>

  <Accordion title="A mobile member cannot sign in on a new device">
    Verify the member's status and reset the registered IMEI when appropriate.
  </Accordion>

  <Accordion title="Workspace members fail to load">
    Confirm the active workspace and network connection, then refresh the page.
  </Accordion>
</AccordionGroup>

## Security and Governance

Workspace membership controls access to potentially sensitive information, including:

- Customer details
- AI-agent configurations
- Knowledge bases
- Conversations and transcripts
- Call recordings
- Campaigns
- API keys
- Phone numbers
- Billing information
- Usage reports

Workspace administrators should:

- Follow least-privilege access
- Review access regularly
- Remove former users promptly
- Restrict billing and payment permissions
- Protect invitation links
- Avoid shared user accounts
- Require strong individual credentials
- Document high-risk permission changes
- Investigate unexpected access
- Follow applicable privacy and employment requirements

<Warning>
  Granting broad workspace access can expose customer information, recordings, credentials, and billing controls. Review every invitation and permission update carefully.
</Warning>

| Page | Purpose |

A person can be a workspace member without appearing in Sales Team performance data.
