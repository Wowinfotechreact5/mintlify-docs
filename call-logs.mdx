Call logs help you understand what happened during conversations handled by your Valuez AI agents.

Use them to:

- Review what the caller and agent said
- Investigate incorrect or incomplete answers
- Check call status and duration
- Review campaign outcomes
- Listen to available recordings
- Understand credit usage
- Identify missing knowledge
- Improve agent instructions
- Investigate failed or unanswered calls
- Maintain evidence for internal quality reviews

Valuez AI currently provides two related history experiences:

| History area | What it contains |
| --- | --- |
| **Agent Conversations** | Browser tests, website-widget conversations, API interactions, and other conversations associated with an individual agent |
| **Campaign Call History** | Telephone calls associated with outbound or inbound campaign activity |

<Info>
  The fields available for a particular record depend on how the conversation was created and what information was successfully captured during that interaction.
</Info>

---

## Agent Conversations vs Campaign Call History

The two history areas serve different purposes.

### Agent Conversations

Open **Conversation History** from an agent to review interactions associated with that agent.

This area is useful for:

- Browser voice tests
- Agent playground conversations
- Website-widget conversations
- API conversations
- Voice-chat interactions
- Text-chat interactions

### Campaign Call History

Open **Campaign Call History** to review calls associated with calling campaigns.

This area is useful for:

- Finding a campaign call
- Reviewing campaign outcomes
- Checking contact and campaign information
- Comparing agents
- Reviewing call duration
- Reviewing credits used
- Playing or downloading available recordings
- Exporting campaign call records

<Warning>
  A conversation may not appear immediately if it is still active or if post-call processing has not finished. Refresh the page after the call has ended.
</Warning>

## Agent Conversations List

Each row represents a recorded conversation associated with the selected agent.

The current list includes:

| Column | Description |
| --- | --- |
| **Conversation ID** | Unique identifier for the conversation |
| **Direction** | Displays the recognized origin or call type label |
| **Channel** | Indicates text, voice, or API processing mode |
| **Call Status** | Current or final recorded status |
| **Date** | Date of the conversation |
| **Time** | Recorded conversation time |
| **Actions** | Opens the full conversation details |

### Conversation ID

The Conversation ID is the most useful reference when investigating a specific interaction.

You can:

- Hover over a shortened identifier to see the full value
- Use the copy action to copy it
- Include it when reporting a problem to support
- Use it to distinguish similar conversations

<Tip>
  When reporting a problem, provide the Conversation ID, agent name, approximate time, and a short description of what went wrong.
</Tip>

## Conversation Origins

The Direction column can display a user-friendly label based on how the interaction entered Valuez AI.

| Displayed label | Meaning |
| --- | --- |
| **Playground** | A conversation created through the agent-testing workspace |
| **Website Widget** | A conversation started through a connected website widget |
| **API** | An interaction submitted through an API |
| **Websocket** | A supported real-time API voice interaction |
| **Other value** | A source value recorded for an interaction not covered by the standard labels |

<Note>
  Older records may use different internal or display labels. Use the channel and detail page together when identifying the interaction type.
</Note>

## Conversation Channels

The Channel column identifies the conversation mode.

| Channel | Meaning |
| --- | --- |
| **Text-Chat** | Text was exchanged between the user and the agent |
| **Voice-Chat** | The user spoke with the agent |
| **API** | Speech or audio processing was used through an API |
| **Other value** | A mode recorded outside the standard display mappings |

The channel does not necessarily tell you whether the interaction was a customer call, browser test, or website-widget conversation. Review the Direction and conversation details for additional context.

## Search, Date, and Sorting

Agent Conversations supports tools for finding historical interactions.

### Date Range

The default view requests conversations from approximately the previous month through the current date.

Change the date range when:

- Investigating an older conversation
- Reviewing activity for a specific business period
- Comparing behavior before and after an agent update
- Performing a weekly or monthly quality review

### Search

Use search to narrow the list where supported.

Useful search values can include:

- Conversation identifier
- Information associated with the recorded conversation
- Other searchable values accepted by the current list

### Sorting

Select **Date** or **Time** to change the sort order.

The indicator shows whether the current order is ascending or descending.

### Pagination

Use pagination and the page-size controls to move through larger result sets.

## Call Transcript

The transcript presents the conversation in speaking order.

Messages are labelled as:

- **Caller / User**
- **AI Agent**

Where timestamps are available, they appear beside individual messages.

The transcript header also shows the number of caller and agent messages.

Use the transcript to evaluate:

- Whether the caller was understood correctly
- Whether the agent used accurate knowledge
- Whether responses were concise
- Whether the agent asked appropriate follow-up questions
- Whether the conversation remained on topic
- Whether the agent invented information
- Whether the agent handled an interruption
- Whether the agent respected its boundaries
- Whether the conversation ended appropriately

### Sentiment and Emotion

Individual transcript messages may display sentiment or emotion information when that data is available.

Treat these values as supporting indicators, not definitive conclusions about the caller.

## Understand Transcript Limitations

A transcript is generated from recognized or recorded conversation content.

It may differ from the exact spoken conversation because of:

- Background noise
- Poor telephone signal
- Speaker echo
- Unusual names
- Product terminology
- Accents
- Fast speech
- Overlapping speech
- Interruptions
- Unsupported language
- Audio loss

When an agent’s answer seems incorrect:

1. Read the Caller / User message.
2. Confirm whether the question was transcribed correctly.
3. Listen to the recording, if available.
4. Determine whether the issue came from speech recognition, knowledge, or agent behavior.
5. Correct the appropriate setting.
6. Test again in a new conversation.

## Call Recording

A **Call Recording** section is displayed when audio is available for the conversation.

Use the recording to:

- Compare the audio with the transcript
- Review pronunciation
- Evaluate speaking speed
- Investigate interruptions

- Review the customer experience

If no recording section appears, a playable recording was not available for that conversation.

<Warning>
  Access, playback, downloading, retention, and sharing of recordings may be subject to privacy and recording-consent requirements.
</Warning>

## Campaign Filters

Campaign Call History supports the following filters:

| Filter | Purpose |
| --- | --- |
| **Campaign** | Shows calls from a selected campaign |
| **Direction** | Narrows calls by inbound or outbound direction |
| **Outcome** | Shows calls with a selected business outcome |
| **Reset Filters** | Clears the active search and filters |

You can combine filters.

Example:

```text
Campaign: October Product Follow-Up
Direction: Outbound
Outcome: Interested
```

This can help you isolate relevant conversations for follow-up.

<Tip>
  Clear filters before assuming that records are missing. A previously selected filter can remain active while you continue working.
</Tip>

- Outcome

Campaign call exports can contain customer and operational information.

Before sharing:

- Confirm the recipient is authorized
- Remove unnecessary personal information
- Use an approved storage location
- Follow your organization’s retention policy
- Do not send exports through unapproved channels

## Review an Incorrect Answer

When you find an incorrect answer, use this process:

<Steps>
  <Step title="Read the user transcript">
    Confirm what Valuez AI understood from the caller.
  </Step>
  <Step title="Listen to the recording">
    If available, compare the transcript with the original audio.
  </Step>
  <Step title="Identify the issue">
    Decide whether the problem came from speech recognition, missing knowledge, outdated information, or agent instructions.
  </Step>
  <Step title="Correct the source">
    Update the relevant agent or knowledge-base setting.
  </Step>
  <Step title="Run a fresh test">
    Use Test Agent to repeat the same scenario.
  </Step>
  <Step title="Review the new conversation">
    Open the resulting history record and confirm that the issue has been resolved.
  </Step>
</Steps>

### Where to Make Corrections

| Problem | Where to fix it |
| --- | --- |
| Incorrect business detail | Business Information |
| Missing service | Services |
| Missing product | Products |
| Missing common answer | FAQs |
| Outdated policy | Knowledge Documents |
| Wrong behavior or tone | Agent Instructions |
| Response is too long | Conversation settings or Agent Instructions |
| Incorrectly recognized speech | Speech to Text |
| Poor pronunciation | Voice & Audio |
| Wrong agent handled the call | Integration or campaign configuration |
| Wrong contacts called | Campaign contacts |

## Quality-Review Workflow

Use call logs as part of a repeatable quality process.

### Daily Review

For active or newly launched agents:

- Review recent failed calls
- Review unusually short calls
- Review long calls
- Review unclear outcomes
- Check customer opt-out requests
- Check calls with missing transcripts
- Check recordings with audio problems

### Weekly Review

- Sample conversations across agents
- Review frequent customer questions
- Identify missing knowledge
- Compare transcripts with recordings
- Review fallback responses
- Review campaign outcomes
- Monitor credit-heavy calls
- Confirm previous corrections remain effective

### After an Agent Change

Whenever you change:

- Knowledge
- Agent instructions
- AI model
- Language
- Voice
- Speech recognition
- Conversation behavior

complete a fresh test and review the new history record.

## Troubleshooting

### No Conversations Are Displayed

Check:

1. The correct agent is open.
2. The date range includes the expected conversation.
3. Search text has been cleared.
4. The conversation has ended.
5. Processing has had time to complete.
6. You have permission to view conversation logs.
7. You are in the correct workspace.

Refresh the page after checking these items.

---

### A Recent Test Is Missing

A conversation may still be active or undergoing post-conversation processing.

Try:

1. End the test normally.
2. Wait briefly.
3. Refresh Conversation History.
4. Extend the date range.
5. Clear the search.
6. Confirm that you tested the same agent.

---

### Campaign Calls Are Missing

Check:

- The correct campaign filter
- Direction filter
- Outcome filter
- Search text
- Current page
- Campaign plan access
- Whether the call was created as a campaign call

Select **Reset Filters** before checking again.

---

### Transcript Is Empty

A transcript may be unavailable when:

- No usable speech was captured
- The call did not connect
- Speech recognition did not complete
- The conversation ended too early
- The record is still being processed
- An audio or provider problem occurred

Check the call status, recording, and timeline.

---

### Transcript Does Not Match the Recording

Possible causes include:

- Background noise
- Overlapping speakers
- Poor signal
- Accent or language mismatch
- Unusual business terms
- Fast speech
- Interruptions

Review the Speech to Text configuration and repeat the scenario in a controlled test.

---

### Recording Is Not Available

A recording may not appear when:

- The interaction did not produce audio
- Recording was not available for that channel
- The call did not connect
- The recording is still being processed
- The audio file is no longer available
- Access is restricted

A transcript may still be available even when there is no playable recording.

---

### Recording Does Not Play

Try:

1. Checking device volume.
2. Confirming the browser tab is not muted.
3. Using another supported browser.
4. Refreshing the detail page.
5. Checking whether other recordings play.
6. Downloading the recording, if permitted.

If only one recording fails, provide its Conversation ID or Call Log ID when reporting the issue.

---

### Call Summary Is Missing

A summary may be unavailable if:

- There was no usable transcript
- The call ended before a meaningful conversation occurred
- Post-call processing is incomplete
- The record does not support summary analysis

Use the transcript, recording, status, and timeline for the available evidence.

---

### Credit Usage Is Unexpected

Review:

- Conversation duration
- Number of retry attempts
- Number of agent responses
- Campaign concurrency
- Whether the call remained connected
- Whether the customer asked many follow-up questions

Compare the call record with Credit Usage before reporting a billing concern.

---

### Export Is Unavailable

Possible reasons:

- Campaign access is restricted by the current plan
- Your account does not have download permission
- No records are available
- The export is still being generated

Confirm plan access and workspace permissions.

---

## Call Review Checklist

Use this checklist when reviewing an important interaction:

- [ ] Correct agent handled the conversation
- [ ] Direction and channel are correct
- [ ] Call status is understood
- [ ] Transcript matches the caller’s meaning
- [ ] Recording was reviewed when necessary
- [ ] Business information is accurate
- [ ] Prices and conditions are correct
- [ ] Agent followed its instructions
- [ ] No unsupported promise was made
- [ ] No confidential information was disclosed
- [ ] Customer objections were handled appropriately
- [ ] Opt-out requests were identified
- [ ] Outcome is supported by the conversation
- [ ] Callback details were verified
- [ ] Required corrective action was recorded
- [ ] Corrected scenarios were retested

## Best Practices

<AccordionGroup>
  <Accordion title="Use the Conversation ID when reporting problems">
    It is the clearest way to identify the exact interaction that needs investigation.
  </Accordion>

  <Accordion title="Check the transcript before changing knowledge">
    The agent may have answered the recognized question correctly even when speech recognition misunderstood the caller.
  </Accordion>

  <Accordion title="Verify summaries against the conversation">
    Do not make important customer, sales, or compliance decisions using only an automatically generated summary.
  </Accordion>

  </Accordion>

  <Accordion title="Protect exported information">
    Store exports only in approved systems and limit access to authorized users.
  </Accordion>

  <Accordion title="Retest after corrections">

  </Accordion>
